# Proyecto Página Web Progresiva

## Historial del proyecto

Resulta preferible realizar varios commits pequeños y coherentes en lugar de un único commit monolítico por las siguientes razones:

1. **Trazabilidad y claridad:** Permite entender exactamente qué cambios se hicieron, cuándo se realizaron y con qué propósito.
2. **Aislamiento y reversión de errores:** Si se introduce un fallo o un error, es sencillo identificar el commit exacto que lo causó y revertirlo sin perder el trabajo anterior.
3. **Facilidad en la revisión de código (*Code Review*):** Revisar cambios breves y enfocado en una sola tarea es mucho más rápido y menos propenso a descuidos para los colaboradores.
4. **Colaboración eficiente:** Reduce drásticamente las probabilidades de sufrir conflictos al fusionar ramas (*merges*) cuando varias personas trabajan en el mismo proyecto.
5. **Documentación viva:** El historial de commits actúa como un diario de desarrollo continuo que explica la evolución del código a lo largo del tiempo.
